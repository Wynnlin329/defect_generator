# Code Review Skill

## 文件目的
本技能用於審查程式修改內容，協助找出功能錯誤、潛在副作用、維護性問題、測試缺口與文件未同步的風險。

本技能為跨專案共用技能，實際需求與規則仍應以專案自己的 `AGENTS.md` 與文件為準。

---

## 一、適用時機

當出現以下情況時，應優先考慮使用本技能：

1. 某項功能已完成，準備進行檢查
2. 修 bug 後，需要確認是否還有遺漏
3. 提交前需要做修改品質檢查
4. 需要快速評估某段變更的風險
5. 需要判斷是否缺少測試或文件同步

---

## 二、輸入內容

本技能輸入可包含：

- 變更前後差異
- 相關檔案內容
- 任務文件
- 需求文件
- 專案背景文件
- 測試檔案
- 相關 log 或錯誤描述

若沒有足夠上下文，不應只憑片段程式碼做過度武斷的結論。

---

## 三、輸出內容

執行本技能後，應至少輸出以下內容：

### 1. Review 摘要
簡述本次審查重點與整體結論。

### 2. 發現的問題
列出程式碼中發現的問題，必要時可分級。

### 3. 風險說明
列出可能造成錯誤、相容性問題、效能問題或維護風險的地方。

### 4. 測試缺口
指出目前可能缺少哪些測試。

### 5. 文件同步需求
指出是否應同步更新 README、需求文件、架構文件或 task 文件。

### 6. 修正建議
提出可執行的改善方向。

### 7. 是否建議合併
給出是否建議進入下一步的判斷。

### 8. 真正修改點建議（若可判斷）
若 review 過程已足以判斷目前修改落點不理想，應盡量指出：

- 問題真正應優先修改的模組 / 檔案
- 目前修改位置為何可能只是表層或症狀點
- 可能需一起檢查的連動區塊

---

## 四、檢查項目

執行 code review 時，應至少檢查以下面向：

### 1. 是否符合需求
- 是否真的完成需求
- 是否偏離原任務範圍
- 是否遺漏驗收條件

### 2. 是否存在明顯 bug
- 邏輯錯誤
- 條件判斷遺漏
- 空值或例外未處理
- 型別或資料格式錯誤

### 3. 是否影響既有行為
- 是否改壞舊流程
- 是否改動共用元件卻未評估影響
- 是否有相容性風險

### 4. 是否容易維護
- 命名是否清楚
- 模組責任是否合理
- 是否有過度耦合
- 是否有重複邏輯未抽離

### 5. 是否有測試缺口
- 是否缺單元測試
- 是否缺整合測試
- 是否缺回歸測試

### 6. 是否有文件缺口
- 對外介面改動是否未更新文件
- 資料流改動是否未更新架構文件
- 使用方式改動是否未更新 README

---

## 五、執行原則

### 1. 先指出高風險問題
若有明顯錯誤或高風險副作用，應優先列出。

### 2. 問題描述要具體
不要只寫「這邊怪怪的」，應說明：
- 問題位置
- 問題原因
- 可能影響
- 建議修法

### 3. 區分嚴重程度
建議至少區分：
- 高風險
- 中風險
- 可改善項目

### 4. 不用為了 review 而過度重構
本技能主要是審查，不是無限擴大任務範圍。

### 5. 若資訊不足，應明說
不要假裝已掌握全貌。

### 6. 若能判斷目前修改點不理想，應指出更合理的修改落點
若問題根源明顯不在目前修改檔案，應明確指出真正較可能的修改入口，而不只評論表面程式差異。

---

## 六、建議輸出格式

建議輸出格式如下：

1. Review 摘要
2. 高風險問題
3. 中低風險問題
4. 測試缺口
5. 文件同步需求
6. 修正建議
7. 是否建議合併

---

## 七、完成條件

符合以下條件可視為完成：

- 已指出主要問題
- 已說明風險與影響
- 已補充測試與文件建議
- 已提供下一步建議
- 已能支援人工判斷是否進入下一階段

---

## 八、不適用情境

以下情況不適合只使用本技能處理：

1. 需求尚未拆解清楚
2. 尚未有任何具體修改內容
3. 任務目標是專門產生測試案例
4. 任務目標是上線前完整版本檢查

上述情況應改用其他技能。
