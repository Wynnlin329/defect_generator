# Test Case Generation Skill

## 文件目的
本技能用於根據需求、程式邏輯與風險點，系統化產出測試案例，提升驗證完整度，並降低功能修改後的回歸風險。

---

## 一、適用時機

當出現以下情況時，應優先考慮使用本技能：

1. 新功能開發完成後，需補測試
2. 修 bug 後，需整理回歸測試情境
3. 任務涉及條件分支較多，需補邊界測試
4. 上線前需要補足測試覆蓋
5. 使用者要求先整理測試案例再開始驗證

---

## 二、輸入內容

本技能輸入可包含：

- 需求文件
- 任務文件
- API 規格
- 程式邏輯說明
- 錯誤描述
- 測試缺陷紀錄
- 既有測試內容

若需求仍不清楚，應先指出測試案例建立的前提不足。

---

## 三、輸出內容

執行本技能後，應至少輸出以下內容：

### 1. 測試範圍摘要
說明這次測試案例針對哪些功能或模組。

### 2. 正常流程測試案例
列出主要成功路徑。

### 3. 邊界條件測試案例
列出上下限、空值、特殊值、順序差異等情境。

### 4. 異常流程測試案例
列出錯誤輸入、錯誤狀態、外部依賴失敗、格式不符等情境。

### 5. 回歸測試建議
若本次任務為 bug 修正或修改舊邏輯，應補回歸測試建議。

### 6. 自動化建議
指出哪些測試適合自動化，哪些較適合人工測試。

---

## 四、測試分類原則

### 1. 正常流程
確認主要使用情境可成功完成。

### 2. 邊界條件
檢查：
- 最小值 / 最大值
- 空值 / null
- 長度限制
- 位置偏移
- 單筆 / 多筆
- 初始狀態 / 已有資料狀態

### 3. 異常流程
檢查：
- 非法輸入
- 格式錯誤
- 欄位缺失
- 第三方服務失敗
- 權限不足
- 逾時 / 斷線 / 無資料

### 4. 回歸測試
檢查：
- 舊功能是否仍可運作
- 修正是否只解一半
- 相鄰流程是否被破壞

---

## 五、執行原則

### 1. 至少覆蓋三大類
正常、邊界、異常三類情境至少都應被考慮。

### 2. 優先涵蓋高風險路徑
若時間有限，應先列最容易造成錯誤或影響較大的測試。

### 3. 測試案例應對應需求或風險
不要產出大量但無法對應目的的測試案例。

### 4. 修 bug 必須考慮回歸
若任務是修 bug，應至少補一組「重現 bug」與一組「修正後回歸」案例。

### 5. 視情況建議自動化
適合穩定重複執行的情境，應建議納入自動化測試。

---

## 六、建議輸出格式

建議輸出格式如下：

1. 測試範圍摘要
2. 正常流程測試案例
3. 邊界條件測試案例
4. 異常流程測試案例
5. 回歸測試建議
6. 自動化建議

---

## 七、完成條件

符合以下條件可視為完成：

- 已涵蓋正常、邊界、異常三類情境
- 已對應本次需求或風險
- 若為 bug 修正，已補回歸測試建議
- 已指出適合自動化與人工驗證的部分

---

## 八、不適用情境

以下情況不適合只使用本技能處理：

1. 需求尚未釐清
2. 尚未知道系統要做什麼
3. 任務核心是程式碼審查
4. 任務核心是建立新專案骨架
